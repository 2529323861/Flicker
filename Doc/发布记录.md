## 构建与打包

### 构建

Unity → File → Build Settings → Windows / x86_64 → Build 到 `Build/`。

`Build/Flicker_BurstDebugInformation_DoNotShip` 是 Unity 标注不要分发的目录，打包时排除。

### 打包

```powershell
$stage = 'pkg/Flicker_v1.1.0_Windows'
if (Test-Path 'pkg') { Remove-Item 'pkg' -Recurse -Force }
New-Item -ItemType Directory -Force -Path $stage | Out-Null
Get-ChildItem 'Build' |
    Where-Object { $_.Name -ne 'Flicker_BurstDebugInformation_DoNotShip' } |
    ForEach-Object { Copy-Item $_.FullName -Destination $stage -Recurse }

Compress-Archive -Path $stage -DestinationPath 'Flicker_v1.1.0_Windows.zip' -CompressionLevel Optimal
Remove-Item 'pkg' -Recurse -Force
```

### 体积参考

| 项 | 大小 |
|---|---|
| 构建产物 | 114.8 MB |
| 压缩后 | **51.4 MB** |

构成：`Managed` 33.8 MB、`UnityPlayer.dll` 29.8 MB、`Flicker_Data` 其余约 40 MB、`MonoBleedingEdge` 8.8 MB。

切 IL2CPP + Strip Engine Code 可去掉 `Managed` 与 `MonoBleedingEdge`，预计降到 25~35 MB，但需要 VS C++ 生成工具。

## GameJolt 更新流程

1. 打开 https://gamejolt.com/dashboard/games/1118559/packages
2. 进 Package `Flicker` → 已有 Release 或新建 Release
3. 版本号按 `MAJOR.MINOR.PATCH` 填
4. Upload Downloadable Build 上传 zip
5. 勾选 **Windows 64-bit**（不勾会显示 Incomplete）
6. 确认启动路径为 `<解压目录>/Flicker.exe`
7. Publish Release → 确认

### 两个已知坑

**① 同名图片会被去重**

替换缩略图时，如果用**相同的文件名**重新上传，服务端会复用旧图片，哈希不变，页面显示的还是老图。换一个文件名（如 `thumbnail-1280x720-v2.png`）才能真正生效。

**② 裁剪数据必须提交**

上传图片后若直接保存，可能返回 `{"errors":{"crop":true}}`。原因是图片已上传但裁剪框未激活。在裁剪区域内点击一次，再保存即可。

## GitHub Release 更新流程

```powershell
# 1. tag 打在当前发布提交上
git tag -a v1.2.0 -m "Flicker v1.2.0"

# 2. 推送 tag
git push origin v1.2.0

# 3. 网页创建 Release
#    https://github.com/2529323861/Flicker/releases/new
#    选择 tag → 填标题与说明 → 拖入 zip → Publish
```

### 注意

- `ProjectSettings/ProjectSettings.asset` 的 `bundleVersion` 必须与 tag 一致
- tag 应打在 `master` 的发布合并提交上，不要打在功能提交上
- 分发包 `*.zip` 已在 `.gitignore` 中，不进仓库，只作为 Release 附件
