## 一、系统机制

### 1.1 获取

- 玩家持有固定数量道具槽，槽位上限由 `ModifierSet.Key.PropSlot` 决定
- 道具按 7Bag 逻辑抽取：当前卡池组成一个包，包内顺序随机，抽完后刷新
- 槽位未满时，`PropContainer.Update` 按 `GetPropCD` / `GetPropCDRate` 推进冷却，冷却归零即发放
- **外部可清空冷却**：把 `propCDRatio` 置 0（如空转轴），下一帧即发放

### 1.2 使用

三层判断，从内到外：

| 层次 | 谁表达 | 机制 |
| --- | --- | --- |
| 自身条件 | 道具 | `CanUse()` 返回 false 则**不消耗、不发布任何事件** |
| 外部否决 | Effect | 订阅 `BeforeUsePropEvent` 写 `cancelled` |
| 效果修饰 | Effect | 订阅 `UsePropResultEvent` |

通过后进入 `BasePropStrategy.OnUse()`。

### 1.3 绑定

道具入槽时由 `PropContainer` 统一注入使用者与容器，因此 `OnUse()` **无参数**，直接使用基类的 `protected` 字段：

```csharp
protected GameCharacterController gameCharacterController;
protected BuffContainer buffContainer;
protected EffectContainer effectContainer;
protected PropContainer propContainer;
```

### 1.4 图标

| 资源 | 路径 |
| --- | --- |
| 道具图标 | `Resources/Images/UI/PropIcon/<path>` |
| Buff 图标 | `Resources/Images/UI/BuffIcon/<path>` |

两目录**不可复用**。`path` 为 `"Unknown"` 时显示占位图。

## 三、实现要点

### 3.1 纯数值修饰类

同起同落的一组修饰放进**一个 buff 的一个 `apply`**，不需要拆成多个 buff。

| 道具 | 修饰 |
| --- | --- |
| 疾行凝胶 | `MoveSpeed ×2.5`、`JumpingCDRate ×0.5` |
| 轻质骨 | `MaxJumpingCD ×0.6`、`StiffenTime ×1.3` |
| 铅制稳定器 | `StiffenTime ×0.5`、`MoveSpeed ×0.7` |

```csharp
effect.apply = (b, m) =>
{
    m.Get(ModifierSet.Key.MaxJumpingCD).AddMultiplier(0.6f);
    m.Get(ModifierSet.Key.StiffenTime).AddMultiplier(1.3f);
};
```

### 3.2 瞬发 + 持续

瞬发部分直接写在 `OnUse()`，持续部分挂 buff。

| 道具 | 瞬发 | 持续 |
| --- | --- | --- |
| 逆流沙漏 | `jumpCDRatio = 0` | `MaxJumpingCD ×1.3` |
| 空转轴 | `propCDRatio = 0` | `GetPropCD ×1.2` |
| 无名光环 | 交换位置（无 buff） | — |
| 借风铃 | 解除僵直 + `ForceJump()` | `HangTime ×1.3` + 取消攻击 |

### 3.3 两段式 Buff

前段由事件终结，后段独立计时。**一个 buff 类内部切换两个 effect**，不写成两个 buff。

```csharp
BaseEffectStrategy frontEffect;   // 前段
BaseEffectStrategy backEffect;    // 后段
float backTimer = 0f;             // 0 = 尚未进入后段

private void OnStageEnd(...)      // 前段结束
{
    effectContainer.RemoveEffect(frontEffect); frontEffect = null;
    backEffect = new BaseEffectStrategy();
    backEffect.apply = ...;       // 后段修饰
    effectContainer.AddEffect(backEffect);
    backTimer = BackDuration;
}

private void OnUpdate(UpdateEvent e)
{
    if (backTimer <= 0f) return;
    backTimer -= Time.deltaTime;
    if (backTimer <= 0f) buffContainer.RemoveBuff(this);
}
```

| 道具 | 前段 | 切换时机 | 后段 |
| --- | --- | --- | --- |
| 羽化孢子 | `HangTime ×0.2` | `AfterJumpEvent` | `MoveSpeed ×0.5` 持续 5 秒 |
| 补偿券 | （无修饰，仅记录命中） | `AfterJumpEvent` | `GetPropCD ×1.5` 持续 7 秒 |
| 脉冲发条 | 锁移动 + 免伤 + 逐帧位移 | 冲刺距离耗尽 | `MoveSpeed ×0.7` 持续 4 秒 |
| 锚爪 | （等待进度） | `AfterJumpEvent` | `MoveSpeed ×0.8` 持续 4 秒 |

**动作型 Buff 的叠层例外**：`isStackable = false`。项目约定"不可叠加用 `isStackable = true, maxStacks = 1` 刷新时长"，但该约定针对限时 buff；按距离/次数终止的动作型 buff 若套用会被吞掉（第二次使用的 `OnAdd` 不执行，道具白白消耗）。

### 3.4 自摘时机

| 时机 | 适用 |
| --- | --- |
| `AfterJumpEvent` | 效果与本次跳跃绑定，落地即结束（羽化孢子前段、锚爪前段） |
| `LandEvent` | **必须保证清理**时。单相、不可取消，即使僵直被取消也会发布（应激、触电、不偏矢的僵直修饰） |
| `UpdateEvent` + 计时 | 后段独立时长（两段式的后段） |
| 事件自带条件 | 逆流沙壶等"等代价兑现后才解除" |

**两段式清理模式**：中段事件施加临时修饰，末段单相事件保证清理。清理若依赖可能被取消的事件（如 `AfterStiffenEvent`），会漏。

### 3.5 轨迹操控类

跳跃的轨迹状态全部在 `JumpContext` 中，效果层通过改字段干预：

```csharp
public bool toRightWall;   // 终点墙（起点墙为其反面）
public float hangTime;     // 秒 → 进度的换算系数
public float progress;     // 0 = 出发墙，1 = 终点墙

public void FoldBack()     // 便捷调用：折返
{
    progress = 1f - progress;
    toRightWall = !toRightWall;
}
```

| 意图 | 写法 |
| --- | --- |
| 折返 | `context.FoldBack()` |
| 改去另一面墙 | `context.toRightWall = !context.toRightWall` |
| 跳到某处 | `context.progress = 目标值` |
| 前进/后退一段 | `context.progress += / -= 增量` |

**`FoldBack` 只是两行常用操作的简写**，没有独立语义、没有副作用、调用两次即完全还原。因此效果可以"提前折返"来抵消弹反帧的折返——**不偏矢就是这样实现的**：

```csharp
// 弹反帧：GCC 无条件折返
context.FoldBack();

// 不偏矢（ParryResult 相位，早于上面那行）
parryResultEvent.context.jump.FoldBack();   // 与弹反帧的折返抵消，净效果为不换向
```

**约定**：不要在 `FoldBack` 中添加副作用（通知、表现、记账）。需要广播"发生了折返"时另立事件。

**视图同步**：飞行协程逐帧比对 `toRightWall` 与已渲染的墙，变化时刷新朝向。因此折返会立刻反映到精灵图，而不偏矢的净零变化不会触发刷新。

### 3.6 两段式条件判定

"未命中才补偿"这类条件，用事件记录状态、落地统一结算。

```csharp
// 补偿券
private void OnHitted(AfterAttackEvent e) => hitted = true;   // 命中
private void OnParried(AfterParryEvent e) => hitted = true;   // 被弹反视作命中

private void OnLanded(AfterJumpEvent e)
{
    if (!hitted) { gameCharacterController.jumpCDRatio *= 0.3f; buffContainer.RemoveBuff(this); }
    else         { /* 切换后段 */ }
}
```

**折返与"是否被弹反"的关系**：锚爪靠 `OnParried` 关闭 `armed` 标志。因为弹反已经改变了轨迹，折返已无意义。

### 3.7 条件使用

`CanUse()` 用于"用出去也没效果"的情况，避免白白消耗。

| 道具 | 条件 |
| --- | --- |
| 无名光环 | 自身处于 `Idle`/`Moving`，且存在同样处于 `Idle`/`Moving` 的敌人 |
| 借风铃 | 自身处于 `Idle`/`Moving`（否则跳跃不会发生，buff 会残留） |

**必须保证"能用"与"执行得下去"一致**——只改 `OnUse` 的守卫会导致 `CanUse` 说能用、执行时空引用。
