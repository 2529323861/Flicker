# 肉鸽地图系统 — 子策划案

> 状态：草案  
> 关联：主策划案「地图系统」&「肉鸽模式敌怪系统」

---

## 一、设计目标

融合以撒的沉浸式房间体验与杀戮尖塔的分支爬塔路线规划，在 Flicker 的双墙战斗框架下，通过「门」的物理隐喻串联关卡，让路线选择成为策略的一部分。

---

## 二、关卡流转流程

```
                    关卡开始
                       │
                       ▼
              ┌─────────────────┐
              │   当前关卡战斗    │
              └────────┬────────┘
                       │ 关卡完成
                       ▼
              ┌─────────────────┐
              │  门打开 + 光球出现 │
              │ （1 或 2 扇门）   │
              └────────┬────────┘
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
     ┌─────────┐  ┌─────────┐  选择门进入
     │ 拾取光球 │  │ 跳过光球 │  （不可回头）
     │（可选）  │  │ 直接进门 │
     └────┬────┘  └────┬─────┘
          │            │
          ▼            │
   ┌─────────────┐    │
   │ 统一奖励 UI  │    │
   │ 获得/替换/放弃│    │
   └──────┬──────┘    │
          │           │
          └─────┬─────┘
                ▼
        ┌──────────────┐
        │ 下一关卡      │
        └──────────────┘
```

### 2.1 门

- 位于关卡顶部，视觉上悬浮在墙壁上方
- 关卡完成后打开
- 一扇门（单向通道）或两扇门（二选一分叉）
- 左墙的玩家跳入左门，右墙的玩家跳入右门
- **进门后不可回头**

### 2.2 光球

- 关卡完成后，在战场**正中央**出现
- 玩家踩踏（跳跃落在光球上）→ 触发战利品拾取
- **可选拾取**：可以不拿直接进门
- 拾取后弹出统一奖励 UI

### 2.3 奖励 UI

- 同一套 UI 覆盖以下场景：
  - **获得**：新道具/藏品直接获得
  - **替换**：道具槽已满时，可选择替换已有道具
  - **放弃**：不想要可以选择放弃
- 藏品直接获得，不涉及替换

## 三、地图结构

### 3.1 整体形态

```
             [起点]
               │
         ┌─────┴─────┐
        [A]         [B]
         │           │
         ├─────┐     │
        [C]   [D]   [E]
         │     │     │
         └──┬──┘     │
           [F]───────┘
           ...
          [Boss]
```

- 非二叉树：有的节点只有一扇门（必经之路），有的是两扇门（分岔选择）
- 节点类型和深度待后续设计（暂定分类方向：战斗 / 精英 / 事件 / 篝火 / 商店 / Boss）
- **全部可见**：游戏开始时整棵地图树全貌展示，供玩家规划路线

### 3.2 不可回头

- 一旦进门即锁定下一关，无法返回上一节点
- 地图上已走过的节点给予视觉标记（如灰色 / 对勾）

## 四、大地图交互

### 4.1 打开方式

| 入口 | 操作 |
|------|------|
| 屏幕图标 | 点击地图图标 |
| 键盘热键 | 按下对应热键（待定，建议 Tab 或 M） |

### 4.2 可用时机

- **随时可打开**：战斗间隙、关卡完成后、奖励 UI 期间均可查看
- 战斗中打开时游戏暂停（待定，取决于是否允许战斗中暂停）

### 4.3 显示内容

- 整棵地图树全貌（节点类型和连接关系）
- 当前所在节点高亮
- 已通过节点标记
- 未来节点类型可见（具体内容如敌怪配置等不可见）

## 五、与双墙机制的衔接

### 5.1 进门操作

```
关卡结束 → 玩家在左墙/右墙 → 按跳跃键 → 跳向对面墙
                                            │
                              如果上方有门 → 进入对应门
                              如果上方无门 → 正常跳跃（战场内）
```

- 门打开后，跳跃轨迹的「上方」被替换为门的判定区域
- 实现上：门打开后覆盖跳跃目标检测，终点改为门的传送触发体积

### 5.2 光球操作

- 光球位于地图正中央（两面墙的水平中点）
- 玩家从任意一面墙跳跃，落点经过光球位置 → 触发拾取
- 光球仅可拾取一次，拾取后消失
- 若跳过光球直接进门，光球消失（不可回头再拿）

## 六、技术要点

| 要点 | 说明 |
|------|------|
| 关卡状态机 | `PreBattle → InBattle → PostBattle(DoorOpen/OrbSpawn) → BranchSelect → Transition → NextLevel` |
| 地图数据 | 树形结构，节点含类型枚举、子节点引用、关卡配置 |
| 门触发 | 跳跃到达门判定区域 → 触发 `EnterDoor(int index)` → 加载对应子节点关卡 |
| 光球触发 | 光球碰撞体 + `OnTriggerEnter` → 弹出奖励 UI |
| 地图 UI | 独立 Panel，从地图数据渲染节点树 |
| 存档 | 当前节点位置 + 已通过路径 + 持有道具/藏品 |
